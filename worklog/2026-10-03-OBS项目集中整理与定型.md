# OBS 项目集中整理与定型

## 做了什么

把工作区中散落的 OBS 仓库、两份原始需求、历次工作总结、初始配置备份和最终验证截图集中到了 `OBS/OBS-talk-demo-studio/`。公开文档和源码放在 Git 管理的目录，本机备份和真实截图留在被忽略的 `local-backups/`。

清理了背景工程依赖、渲染中间图、两版旧安装测试和过期测试截图，移入回收站的内容约 665.0 MiB。正式背景视频、遮罩、边框、源工程和 Git 历史全部保留。

同时备份了当前场景配置与桌面控制条快捷方式，把 OBS 的运行素材路径改为自身固定素材目录，并修正快捷方式指向。最后在项目里写入了后续修改及时提交并推送 GitHub 的维护约定。

## 为什么做

项目已经基本定型，继续把测试图、旧模板和依赖散放在工作区里，会让人分不清哪个才是正式版本。目标是只留下一个明确的项目入口，又保留日后复现和排查所需的源文件。

## 值得记住的决策、坑或技术点

- 搬仓库不能只移动文件夹：OBS 的视频源、边框和遮罩原来都引用仓库绝对路径，桌面控制条也一样。这些引用必须一起更新。
- 运行素材改放 OBS 自己的素材目录，以后移动仓库就不容易把画面搬坏。之后更新素材，要记得同步更新运行副本。
- 清理的是可再生或已被替代的产物，初始配置备份、正式素材和源码仍然保留。清理内容可以从回收站找回，回收站未清空前不等于释放磁盘空间。
- 本机备份和真实桌面截图不推送到公开仓库；脱敏模板、原始需求和工作总结才进入版本管理。
- “实时上传”落实成每次有效修改验证后，在同一轮里提交并推送，推送失败就明确说明。维护约定放进 `AGENTS.md`，以后接着改也不会忘记。

## 一句话亮点

把散落一桌的 OBS 实验，收成一个有正式版本、有历史、有备份、改完就同步的个人录制工作台。
