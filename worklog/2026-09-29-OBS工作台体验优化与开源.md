# OBS 工作台体验优化与开源

## 1. 做了什么

把原来偏重的快捷键体系收成了五个：`Alt+1/2/3` 切三个核心场景，`Alt+Z` 做重点缩放，`Alt+R` 控制录制。删除了和全屏录屏几乎一样的“重点演示”场景，把它变成录屏过程中的动态缩放状态。

重新设计了“电脑录屏 + 真人小窗”：用深绿科技背景、暗色卡片、柔和阴影、翡翠强调线和 JED 品牌签名，替换了原来的纯色背景与生硬白框。点击提示也不再是一个突然出现的静态圆圈，而是修改 Zoominator 源码做成三层同心水波，轻柔扩散后渐隐。

最后把脱敏后的场景集合、1440p30 配置、插件参数、背景素材、安装/备份脚本、源码补丁和自动构建流程整理进公开仓库 `jedliuai/OBS-talk-demo-studio`，并发布了 `v1.0.0`。

## 2. 为什么做

原来的配置功能很多，但使用时需要记太多组合键，而且“重点演示”和“全屏录屏”没有真正的视觉差异。真人小窗也更像临时叠上去的画面，点击光圈存在感和质感都不理想。这次目标是让日常录制更像一个成熟产品：选择少、反馈清楚、视觉统一，并且换电脑后还能从 Git 恢复。

## 3. 值得记住的决策、坑或技术点

- 场景是稳定构图，重点演示是临时状态；两者不要混成四个并列按钮。
- 快捷键用“数字管画面、字母管动作”的分组，记忆成本明显低于多组 Ctrl/Shift/Alt 组合。
- 小窗边界不能只靠白框，尤其面对浅色网页时；暗底、阴影和一条高饱和强调线更稳。
- Zoominator 的点击标记原本只改透明度。真正像水波，需要同时改标记图形、生命周期和 Scene Item 的缩放曲线，而且代码里有两条更新路径，第一次云端编译正是漏改了第二个调用点。
- GitHub Actions 从固定的上游标签拉源码、应用公开补丁并构建，最终 DLL 经过 Defender 扫描；发布包安装时还会校验 SHA256。这样比直接保存一个来源不明的 DLL 靠谱得多。
- 公开仓库只放模板：摄像头 ID、显示器 ID、WebSocket 密码和真实桌面截图都不能跟着上传。

## 4. 一句话亮点

把 OBS 从“快捷键很多的工具箱”，收拾成了一套五键可控、点击有水波、画面有品牌感、还能一键复现的个人 IP 演示工作台。
