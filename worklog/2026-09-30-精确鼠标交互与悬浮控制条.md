# 精确鼠标交互与悬浮控制条

## 1. 做了什么

把鼠标跟随快捷键从会和浏览器冲突的 `Alt + F` 改成了与缩放键相邻的 `Alt + X`，并恢复、实测了跟随的开启、冻结和再次开启。新增了一条午夜蓝风格的悬浮控制条，可以直接点击切换三个场景、缩放、鼠标跟随和录制，而且已经在桌面生成了快捷方式。

Zoominator 也做了一次更深入的改造：点击水波变得更大、更慢，点击坐标改为根据被捕获窗口的客户区、OBS 场景变换和 Windows DPI 共同计算；同时增加了只存在于 OBS 输出画面里的蓝白指针光环。新版插件已经通过 GitHub Actions 编译，安装到本机，并发布为 v1.4.0。

## 2. 为什么做

之前的点击光圈是按整块显示器估算位置，而实际录制的是浏览器窗口，所以窗口边框、场景缩放和 150% 系统缩放叠加后会产生明显偏移。原来的光圈也太小、消失太快，观众很容易错过。系统光标本身如果直接放大，又会改变自己的操作体验，因此需要把“观众看到的增强”和“操作者使用的光标”分开。

控制条则是为了解决快捷键记忆成本：功能仍然保留，但不要求每次都回忆按键。

## 3. 值得记住的决策、坑或技术点

- 鼠标坐标不能只按显示器宽高同比换算，窗口捕获必须使用实际客户区，再经过 OBS 的绘制矩阵，才能兼容留白、裁切和场景缩放。
- 这台电脑启用了 150% Windows 缩放。Qt 给出的逻辑坐标和 Windows/OBS 使用的物理像素不是同一个坐标系，第一次修正窗口范围后仍有约三分之一偏差，最后增加了逐显示器 DPI 转换才真正对齐。
- 浏览器标题会随着活动标签和标签数量变化。窗口匹配先按标题、类名和进程查找，标题变化时再退回稳定的类名与进程，避免突然失效。
- 光标增强采用 OBS 场景叠加，不修改 Windows 系统光标；真人全屏场景也不会出现它。
- 悬浮控制条使用 Windows 的捕获排除标记，实测返回值为 `0x11`。这比依赖裁切画面更稳，也不会要求开启 OBS WebSocket 密码。
- 水波的指针位置和增强光标位置已实测完全一致；`Alt + X` 关闭跟随后移动鼠标，录屏画面保持冻结，再次按下后会继续跟随。

## 4. 一句话亮点

把 OBS 的鼠标交互做成了“我操作时毫无负担，观众看时处处清楚”的双层体验：精准水波、专属光标和不会入镜的控制台一次到位。
