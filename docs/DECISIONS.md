# 设计决策

## 为什么把“重点缩放”并入录屏场景

独立的“重点缩放”场景和缩放工具承担了同一件事，既增加场景数量，也让人需要判断该切场景还是按快捷键。现在只保留 `02 电脑录屏 + 真人小窗`，由 `Alt + Z` 在鼠标附近平滑放大或恢复软件来源；真人小窗、动态背景和品牌信息始终不动。`03 电脑录屏全屏` 继续承担最大可读面积的纯屏幕画面。

## 为什么场景快捷键使用连续数字

三个主场景固定使用 `Alt + 1/2/3`，顺序就是“人 → 带人讲解 → 纯屏幕”。`Alt + Z` 在鼠标附近放大或恢复，紧邻的 `Alt + X` 开关鼠标跟随，`Alt + R` 负责录制。原来的 `Alt + F` 会和浏览器功能冲突，因此不再使用。所有动作也同时出现在捕获排除的悬浮控制条上，不想记快捷键时可以直接点击。

## 为什么背景换成「深蓝工作室 / 暖纸桌面」

旧的午夜蓝斜线流光是通用科技素材，换给任何博主都成立，正是个人品牌片里明确不要的「科技蓝光效」。新背景只从已有品牌资产里取材：深蓝工作室复刻头像里的灰蓝墙面、左下蓝色补光和背光 jed 墙标，让观众觉得录屏和真人出镜在同一间工作室；暖纸桌面延续品牌片 v007 与领英 banner 的暖纸、陶土色和压印 jed 字标。两套共用同一套几何（`motion-background/src/layout.ts`），只换材质，`02` 场景里点眼睛图标切换。

动效只保留墙面光和补光的缓慢呼吸、窗光在纸面上缓慢移动、品牌圆点轻微起伏，全部是 12 秒周期函数，首尾无缝。录屏时背景只负责安静地托住内容。

## 为什么录屏放进卡片、圆窗缩到 440px

旧布局录屏区左右边距不对称（48px / 272px），500px 圆窗压进录屏右侧约 288px，正好挡住网页的发送按钮和滚动条。现在录屏卡片四边对齐，窗口捕获在卡片内按比例居中，非 16:9 窗口留出的边就是卡片底色，看起来是有意的边框。440px 圆窗底边与卡片底边对齐，只压住右下约 112px。

## 为什么圆窗边框改成暖白实色细环

冰蓝发光圆环和背景的科技感叠在一起，显得廉价。新边框是 9px 暖白实色环，上亮下暗模拟受光，内外各一圈极淡细线分隔画面，再加一层只落在圆外的柔和投影。同一张边框在深蓝和暖纸两套背景上都成立，所以切换背景不用动边框。品牌圆点画在背景里，悬在圆窗正上方，呼应 jed 里 j 的那个点。

## 为什么标题、网址、身份条都放到后期

录制时要顾表达、操作和快捷键，再多一个「改本期标题」「开关身份条」就会分心。OBS 画面只保留不会过时的名字与定位；顶栏右侧刻意留空，后期加的本期标题可以直接放进去。

## 为什么放大跟随会「飘」，以及怎么调的

两处原因叠加：一是跟随速度 7.0，鼠标每动一点画面就立刻跟着平移；二是 900ms 静止冻结，Zoominator 冻结时改用画布中心做锚点，跟随时用鼠标位置做锚点，于是每次鼠标停下近一秒画面就跳一下，再动又跳回去。现在关掉静止冻结（0），跟随速度降到 2.2，画面像镜头一样滑过去；放大倍率 1.8 → 1.6，平移幅度更小、上下文更多；放大与恢复动画放慢到 420ms / 480ms。

## 为什么改成「死区跟随」

调慢速度只能缓解：只要鼠标在动，画面就跟着平移，讲解时指着按钮晃两下，观众就会觉得镜头在飘。现在参照 Screen Studio 的思路，在插件里加了死区：放大后，鼠标在当前可视区域中间约 60% 的安全框内移动时画面完全不动；只有鼠标进入边缘带，镜头才平移，而且只移到刚好让鼠标回到安全框边上为止。

平移用临界阻尼弹簧，约 450ms 稳定，起步和停下都柔和，不会冲过头。安全框按「镜头正要去的位置」计算，而不是按当前正在滑动中的位置，所以镜头能干净地停住，不会一点点蹭。目标位置也被限制在画布能显示的范围内，避免鼠标贴边时目标跑出去、回头时镜头先“发呆”一段。

顺手修了两个跳变：原来 `Alt + X` 关闭跟随或静止冻结时，锚点从鼠标位置换成画布中心，重新打开跟随时又直接跳到鼠标当前位置。现在暂停和恢复都沿用同一个锚点，画面原地停住、原地继续。

没有加新快捷键：`Alt + Z` 放大、`Alt + X` 开关跟随保持不变。两个新参数 `follow_deadzone_pct`（默认 60，0 表示回到旧的连续平滑）和 `follow_spring_ms`（默认 450）都在 Zoominator 设置对话框的「鼠标跟随」里，也写进了模板。

## 为什么点击反馈改成 0.5 秒的一次扩散

之前的三圈蓝色同心环从 0.72 倍扩到 3.35 倍、持续约 1.3 秒，像雷达波：点一下要吵一秒多，连续点击时圈套圈，反而盖住了被点的按钮。现在参考 Screen Studio，把反馈分给光标和点击点两处，总共约半秒：

- 箭头按下时 60ms 内缩到 0.86，松开后约 180ms 弹回，中间轻微过冲到 1.06，像真的按了一下；
- 点击点出现一个灰蓝实心圆，从 13px 缓出扩到 30px，透明度从 0.32 降到 0，约 450ms；
- 外面一圈 2px 白色细环，从 24px 扩到 42px，透明度从 0.42 降到 0，约 500ms。

插件读不到光标下方界面的亮度，所以用中性色：灰蓝实心圆在白底和深色编辑器上都能看出来，白色细环两侧各带一道 1px 的深色描边，白底上也有轮廓。浅色和深色背景各渲染对比过一次，原方案在白底上偏淡，所以实心圆起始透明度从 0.26 提到 0.32，细环描边从 25% 黑提到约 39% 黑，深色背景上几乎没有变化。尺寸按 1080p 画布设计，画布更高时按比例放大。

## 为什么录制画面里用干净箭头替换系统光标

直接放大 Windows 系统光标会改变操作者的手感，也会影响日常使用，所以光标增强只出现在 OBS 画面里。之前的做法是在系统箭头上再叠一个 64px 的准星光环，录出来两样东西挤在一起，显得乱。现在改成只留一个光标：插件在 OBS 场景顶部画一个干净箭头（系统箭头的 1.5 倍，白色填充、#111 约 1.5px 描边、圆角转折、向下约 3px 的柔和投影），同时让它管理的窗口捕获和屏幕捕获不再采集系统光标。箭头带约 60ms 的临界阻尼平滑去掉抖动，箭尖就是热点；点击效果始终用真实点击坐标，不用平滑后的位置。

代价是录制画面里只有箭头：文本输入的 I 形光标、链接上的手形光标、调整窗口大小的双向箭头都会显示成普通箭头。讲解时一般不影响理解，需要原样光标时，在 Zoominator 设置里关掉「用干净的箭头替换系统光标」即可。

系统光标的开关交给插件，不改场景文件：插件只在自己真的画箭头时，才关闭所管理捕获源（窗口捕获的 `cursor`、屏幕捕获的 `capture_cursor`）的光标采集；关掉替换、关掉光标效果，或改用没有这个功能的旧插件之前先关掉替换，系统光标都会回来。这样安装顺序不会出现「画面里一个光标都没有」的空档，也不用手改场景文件，摄像头和窗口选择不受影响。模板里的捕获源仍保持采集光标，没有新插件时也不会丢光标。
